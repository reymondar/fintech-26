# Stackhouse CMS — Payload

## Start locally

`npm run dev` then open http://localhost:3000/admin and create the first owner. No Payload account is needed. Local data is in ignored `data/payload.db`; media uploads in ignored `public/media`. Never commit .env.local.

`npm run cms:import` imports missing MDX posts only, preserving slugs, publication dates, keywords and draft status. Existing CMS posts are never overwritten. The original MDX is retained in the repository and as an authenticated-only source field. Inline SVG charts are extracted into public/blog SVG assets. Tables are converted to Lexical tables (Payload labels this feature experimental).

Set `CMS_BLOG_ENABLED=true` only after import. When disabled, the original filesystem remains the blog source; when enabled, Payload is authoritative (including unpublished/deleted posts). Blog, sitemap, Markdown and llms routes read published content from the CMS at request time. The AI indexes are generated from content/ai templates, not edited in public anymore.

## Features

- /admin: Spanish editor, rich text, tables, media, image/FAQ/button blocks, SEO title separate from H1, canonical, noindex and social image.
- Drafts, autosave, versions, scheduled publishing. Versions keep all history; storage grows accordingly.
- Authenticated preview via /api/cms/preview, desktop/mobile viewport controls. The preview loads saved drafts; it is not the Enterprise click-to-edit editor and does not stream each keystroke.
- Slug changes create permanent HTTP 301 redirects. Deleted posts are not resurrected from old files. Old draft posts return 404 publicly.
- Append-only changes on publication; authenticated export at /api/cms/changes. Timestamps indicate publication in CMS, not confirmed Google crawl or measurement outcome. Autogenerated snapshots are not a full compliance audit. Deleted content and media require an export/backup for restoration.
- Resend email adapter uses the existing RESEND_API_KEY and FROM_EMAIL variables for password resets. Verify the sender in the deployed environment.

## Deploy on Vercel

Required environment: PAYLOAD_SECRET (random, persistent), DATABASE_URL (persistent PostgreSQL, e.g. Neon), BLOB_READ_WRITE_TOKEN, CMS_BLOG_ENABLED=true, NEXT_PUBLIC_SITE_URL=https://thestackhouse.io. Do not deploy file-based SQLite to Vercel: its filesystem is ephemeral. Neon is connected as of 2026-10-16. The initial PostgreSQL migration and 16-post import were applied to the isolated stackhouse_cms schema; existing audit tables in public and neon_auth were preserved. Persistent image storage and the production scheduler still need configuration.

For future schema changes, generate/review Postgres migrations against PostgreSQL (not the local SQLite config): `npm run payload -- migrate:create`, then `npm run payload -- migrate` before enabling the CMS. Run `npm run cms:import` against that database before changing the blog source. PostgreSQL automatic schema push is disabled. Payload uses the isolated stackhouse_cms schema by default (PAYLOAD_DB_SCHEMA override). Review and apply migrations explicitly; other apps can keep their own schemas.

Create the owner with a one-time explicitly enabled setup: PAYLOAD_ALLOW_SETUP=true, register at /admin, then disable the variable. The proxy blocks /api/users/first-register on Vercel otherwise. A signup window must never be left open on an uninitialized public deployment.

Scheduled publishing needs an external scheduler on Vercel calling `/api/payload-jobs/run?queue=default` with `Authorization: Bearer CRON_SECRET` at the desired cadence. Local autorun is disabled on Vercel. No scheduler or paid subscription is provisioned automatically. Avoid enabling a Vercel cron frequency unsupported by the current plan.

Back up PostgreSQL and original uploaded media independently. Establish retention and verify a restore. No enterprise license is required for the implemented core.

## Scope

This installation connects the blog. Existing services/landing pages remain managed in code. A future Pages collection and entity/reference models are needed to let editors manage those pages; the complete six-point wish list is not claimed as finished. Advanced custom Schema and hreflang for translated articles remain future work.

## Verification status

`npm run cms:check` uses a separate temporary SQLite database and checks draft access, publishing, publication snapshots, unpublished edits, redirects, version history and unpublishing. `npx tsx scripts/verify-import.ts` checks all MDX imports against their original dates, headings, tables and links. The local API returns 404 for the draft and 401 for unauthenticated history export.

The lockfile audit still reports upstream/transitive advisories in Payload dependencies (including Sass/chokidar/braces and Drizzle tooling), as well as legacy gray-matter parsing dependencies. Compatible fixes were applied; no forced major downgrades were applied. Recheck these before production rollout.


## Herramientas editoriales ampliadas

El campo de revisión SEO muestra errores bloqueantes y recomendaciones, junto con simulaciones de Google y redes. Solo se valida al publicar; guardar borradores incompletos está permitido. Los enlaces internos del editor y del bloque Botón se guardan como referencias a artículos y resuelven su slug actual. Los enlaces externos tienen opciones nueva pestaña, nofollow y sponsored. No se comprueba disponibilidad HTTP de todos los enlaces externos.

Imágenes: usar el botón de archivo del editor para seleccionar o subir a la biblioteca. El alt y pie pueden tener un valor específico por artículo; los valores de la biblioteca se usan como alternativa. Las dimensiones se incluyen en HTML para evitar saltos de layout. El bloque Imagen por URL queda para compatibilidad con las importaciones.

Bloques: preguntas/respuestas, definición, estadística con fuente/fecha, ficha Service/Product, comparativa, vídeo HTTPS (YouTube/Vimeo/MP4/WebM), botón y sección reutilizable. Comparativas con celdas desiguales bloquean publicación. Los vídeos muestran un resumen/transcripción en HTML. Las secciones reutilizables tienen versiones, consulta de usos y registro por URL publicada al guardar; se desactivan en vez de borrarse. Desactivar retira el bloque de todos sus usos.

Schema: Article y BreadcrumbList se generan en la página. FAQPage, DefinedTerm y Service/Product se derivan de los bloques visibles. Schema adicional admite un objeto o array de tipos permitidos; reemplaza entidades generadas del mismo tipo. Validación básica de estructura, no certificación completa de Schema.org ni garantía de rich results. Cualquier Schema personalizado debe describir contenido visible. Los valores se escapan al insertar JSON-LD.

Historial: lista nativa con filtros, enlace de exportación CSV/JSON. Endpoint autenticado `/api/cms/changes` acepta `url`, `kind`, `from`, `to` (fechas ISO), `format=csv`. El enlace del panel exporta todo; los filtros de la lista no se aplican automáticamente al enlace. CSV neutraliza fórmulas. Las versiones se restauran desde la vista nativa de Payload.

Scheduler preparado: `.github/workflows/cms-scheduler.yml` ejecuta la cola una vez por hora (minuto 7), además de ejecución manual. Requiere secretos de GitHub `CMS_SITE_URL` (URL del sitio publicado) y `CMS_CRON_SECRET` (igual al `CRON_SECRET` de Vercel). No se activó ni desplegó desde esta tarea. GitHub puede retrasar u omitir ejecuciones; no prometer puntualidad exacta. Revisar cuotas/minutos de Actions de la cuenta. Para publicaciones con mayor precisión, configurar un scheduler de mayor frecuencia según presupuesto.

Pruebas aisladas: `npm run cms:check` y `npm run cms:check:editorial` usan SQLite temporal. No modifican los artículos de Neon. Checklist de entrega: `CMS-TODO.md`.
